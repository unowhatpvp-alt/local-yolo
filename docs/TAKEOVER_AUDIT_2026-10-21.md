## 2. 第一阶段十个问题

### 2.1 最初的设计目标是什么？

从 `main` 的 README、初始交付文件以及实际架构可确认：这是一个保护本地媒体隐私、无需推理后端、可通过 GitHub Pages 分发的浏览器 YOLO 工作台。核心业务是选择或导入模型，处理摄像头/图片/视频，在本地推理、显示结果并导出。界面支持中文/英文、明暗/系统主题、桌面和触摸设备。

随后明确记录的 Minimal V1.1 目标是：保持黑白灰简洁风格，减少首页与工作台信息密度，将设备、镜像、倍率和导出放入按需菜单；在线模型升级为完整的 YOLO26 五任务、五尺寸。用户本轮再次明确：**第一版本优先完成 UI 简化、交互优化和稳定性，推理正确性为质量底线，不增加大量新功能。**

仓库没有更早的完整产品规格书、用户访谈或任务工单。不能据现有文件推断商业用途、性能 SLA、模型准确率目标或 Studio/训练产品需求；这些属于“目标待确认”。

### 2.2 目前是什么类型的软件？

纯静态浏览器应用/PWA，使用 JavaScript ES Modules、Vite、ONNX Runtime Web 1.23.2、Web Worker、WASM/WebGPU、Canvas 和 IndexedDB。运行时不需要 Python 服务、用户账户、API Key 或远程推理。Python、FFmpeg 和 Node 在本项目中是开发验证工具，不是用户部署所需后端。

媒体由本地文件选择或摄像头取得；在线模型需要通过 HTTPS 下载，应用随后校验并尝试缓存。静态托管和首次模型下载属于网络依赖，不能描述为首次打开就完全离线。

### 2.3 计划支持哪些核心功能？

可确认的范围如下：

1. 在线 YOLO26：Detection、Segmentation、Pose、Classification、OBB，各 N/S/M/L/X，共 25 个具体 ONNX 导出。
2. 支持格式范围内的本地 ONNX 导入；YOLO11 Nano 五任务作为保留的兼容回归，不能替代 25 个 YOLO26。
3. 摄像头、上传图片、上传视频；串行真实推理、结果叠加、置信度调整、镜像和与实际相机能力相符的倍率操作。
4. 模型选择、下载进度、完整性检查、取消、缓存识别、缓存清理和存储失败后的可理解反馈。
5. WASM 和可用设备上的 WebGPU；初始化/真实预热失败时进行实际 WASM 回退。
6. 检测框、实例掩码、人体关键点、分类结果、旋转多边形；正确的原图坐标映射。
7. PNG/JSON 导出、中英文、主题切换、桌面/手机横竖屏/平板布局、全屏、工具栏淡出恢复及触摸操作。
8. GitHub Pages 子路径部署、PWA shell/运行时缓存、缓存模型离线推理、明确触发的版本更新和恢复路径。

不在可确认的第一版本范围内：浏览器训练、Studio 高级工作台的完整功能、通用任意 ONNX 网络、任意外部权重文件、任意多输入网络、自动访问所有 iPhone 物理镜头。保留入口不等于承诺这些已实现。

### 2.4 哪些功能已经完整实现？

接手时开发分支已经包含完整的 Minimal UI、五任务适配器和绘制器、25 项固定模型清单、图片/视频/相机生命周期、导出、缓存、中英文、主题、全屏回退和 PWA 代码。历史记录不只是静态声明：存在逐模型原始结果、输出张量统计、真实视频帧记录和 PNG；GitHub 原始日志也显示实际执行。

但“已实现”必须与“本轮已验证”分开。接手后的 UI/core 修改改变应用指纹，原先通过的 25 模型记录不能自动继续代表新版本。最新本轮结果见第 5 节；尚在执行的浏览器/设备/PWA 项目不在这里提前判定为完成。

### 2.5 哪些功能只有部分完成？

- UI 简化结构已成型，但菜单键盘导航、焦点回收、滑杆与菜单事件边界、全屏淡出/恢复仍需要完善并回归。
- 静态 PWA 和生命周期测试已经实现；接手时完整安全浏览器离线/两版本更新/存储恢复链路尚未跑完。
- WebGPU 有实际加载与回退路径；接手时保存的 25 条兼容结果是安全浏览器内的真实 WASM 回退，不是 25 个硬件 WebGPU 通过。
- 手机/平板有响应式实现及历史 Chromium 视口观察；物理 Safari/iOS 安装、镜头、原生 zoom、后台恢复和原生全屏缺少对应设备观察。
- 缓存与异常处理已存在，接手审查仍发现取消与校验时序边界；本轮补充修复和测试。
- 开发分支具备构建能力，但验收、文档状态、CI 与生产发布还没有完成闭环。

### 2.6 哪些功能尚未实现？

三个预留入口没有 Studio 高级推理或训练实现，页面明确显示开发中：`/studio/`、`/experimental-training/`、`/studio/experimental-training/`。它们保留为路线图入口，不列为本轮推理版本必须新增的功能。

在已经确认的 Minimal 核心范围中，没有证据支持“整个图片推理或某个任务完全不存在”的判断；主要剩余工作是现有交互缺陷、稳定性边界、真实验证及发布闭环。没有明确记录的额外产品功能应标为“目标待确认”，不能为了填满交付清单擅自开发。

### 2.7 是否存在未完成代码、占位或临时实现？

有：上述三个预留页面；测试报告中 `pending`、`environment-unavailable`、`unverified` 和浏览器渲染的人工复核待办；多份最终验收文档仍描述更早的失败阶段。

此外，开发工具包含独立测试 harness，属于开发验证入口，不应进入正式静态包。它不会替代用户界面，也不能因为 harness 推理成功就自动把用户界面检查写成通过。没有发现核心推理通过返回固定伪检测结果来占位的实现。

### 2.8 是否存在重复、冲突、废弃或不用的代码？

明确发现的是**文档状态冲突**：`START_HERE_zh.txt` 仍写 V1/仅开放 YOLO11 Nano，而开发版清单已经是 YOLO26 25 项；README、DELIVERY、BROWSER_VALIDATION、PWA_VALIDATION 和部分 CI 收据仍引用更早的 GPU/PWA 缺口与测试数量。应统一当前入口说明，同时保留历史诊断。

`public/` 中三个相似页面是不同路线图 URL 的独立入口；`docs/diagnostics/` 与 `docs/evidence/` 的多批结果是有版本意义的历史证据。不能仅因内容相近就删除。当前没有完成覆盖所有文件的“绝无死代码”证明，不作这一承诺；本轮没有进行无必要的大规模清理或重构。

### 2.9 此前中断是否留下不完整修改？

是，但目前能证明的是**未完成的验收链路和状态收据**，而不是已证明源码缺失或 Git 对象损坏。开发分支包含完整已提交实现，并保留了若干中断/失败诊断文件；线上仍停留在原 V1。

最新接手前 CI 在实际浏览器阶段中断：全屏退出操作返回后立即读取 `body.is-fullscreen`，异步 Fullscreen API 尚未完成，断言得到 `true !== false`。后续缓存删除和 PWA 两版本更新等步骤因而没有执行。前一批 CI 还在即时 resize 后的响应式测量失败。不能把这些尚未执行的后续步骤写成通过。

本轮使用独立工作副本和开发分支继续处理，没有覆盖用户其他目录中的未知修改，也没有重写历史、强推或修改游戏/系统文件。

### 2.10 目前能否独立运行和发布？

**能以开发服务器或静态 HTTP(S) 服务独立运行并构建；接手时不具备正式发布验收结论。** 所需运行时可打包为同源资源，Pages 基路径为 `/local-yolo/`；不需要后端推理服务器。不能把它当作双击即用的单文件 HTML。

接手时线上 V1 有成功发布记录，而 V1.1 的最新 CI 失败、PWA 验收未闭环、硬件和设备覆盖有限。本轮构建通过也不足以单独批准发布；需要完成当前源码的模型、浏览器、PWA、CI 和静态资源检查后判断。
